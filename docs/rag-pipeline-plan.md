# RAG Pipeline for Medical Chat

## Context

The Day10 medical chat UI (`src/views/Day10/`) currently uses four static prompt templates (General, Symptom Checker, Medication, Emergency) to guide the LLM. Responses are entirely dependent on Gemma 2 9B's training data with no grounding in real medical literature. The goal is to add a RAG pipeline that retrieves relevant PubMed abstracts for each user query and injects them as evidence into the LLM prompt, improving factual accuracy and enabling citation-style responses.

**Constraint**: Gemma 2 9B has `supportsSystemRole: false` — system prompts get prepended to the **first** user message, not sent as `{role:'system'}`. This shapes the injection strategy.

---

## Architecture

```
User Query
    ↓
POST /api/chat (route.ts)
    ↓
[NEW] RAG Retrieval
  lastMessageContent → MiniSearch BM25 index → top-3 PubMed chunks
    ↓
[NEW] Augment systemPrompt
  augmentedSystemPrompt = systemPrompt + "---\nRELEVANT MEDICAL LITERATURE:\n..." 
    ↓
[EXISTING] Cache check (uses hashPrompt(augmentedSystemPrompt) — no schema change)
    ↓
[EXISTING] Gemma injection: augmentedSystemPrompt prepended to first user message
    ↓
streamText → Gemma 2 9B
```

**Why augment `systemPrompt` not last user message**: Cache key (`systemPromptHash`) automatically captures RAG results. The injection logic in `route.ts` (lines 241-261) handles Gemma's no-system-role constraint unchanged. RAG context persists across turns in the system context — appropriate for medical consultations.

## MiniSearch Index Config

```typescript
// search fields with boost weights
boost: { title: 3.0, meshTerms: 2.5, abstract: 1.0 }
fuzzy: 0.15     // handles typos in medical terms
prefix: true    // "hypertens" matches "hypertension"
limit: 5 → return top-3 above score threshold 1.0
```

**Why BM25 (MiniSearch) over embeddings**: Medical terminology is precise — keyword search performs as well as semantic search for in-domain queries, requires no additional model server, is deterministic (same query always returns same results → stable cache keys), and is < 5ms per query (in-memory).

Appended to `systemPrompt` before injection:

Use the above evidence to ground your response. Cite [1], [2], etc. where applicable.

Token budget: ~600 tokens for 3 citations. Gemma 8K context: ✓

## Notes

- **No Prisma schema change** — `systemPromptHash` already covers the augmented prompt
- **Graceful degradation** — if `data/pubmed/` is missing or retrieval fails, chat continues without RAG context (empty string appended)
- **Cache isolation** — RAG results are deterministic (BM25), so identical queries produce identical hashes → cache still works correctly
- **First-request latency** — index builds lazily on first request (~50–100ms for 800 docs); subsequent requests reuse the singleton
- **NCBI rate limit** — 3 req/s without API key; fetch script sleeps 400ms between batches
- **Specialized topics** — cardiology, oncology, neurology, endocrinology (all confirmed by user)

## Clinical Query Filter

RAG is injected **only for clinical queries**, not for greetings or casual short messages. Two-layer filter (fast → slow):

**Layer 1 — Word count guard** (< 1ms): Skip retrieval if message has fewer than 4 words.

**Layer 2 — Score threshold** (already built-in): MiniSearch returns results only above `minScore = 1.0`. Greetings like "hello" or "thanks" match no medical abstracts → 0 results → empty context block → no injection. This is the primary filter.

```typescript
function shouldAttemptRag(message: string): boolean {
  const wordCount = message.trim().split(/\s+/).length;
  return wordCount >= 4;
}

// In route.ts RAG block:
if (systemPrompt && lastMessageContent && shouldAttemptRag(lastMessageContent)) {
  // ... retrieve and inject
}
```

This means retrieval is skipped for short phrases, and naturally skipped for non-clinical messages because they score below the MiniSearch threshold. No complex keyword allowlist required.
